TEIL 2 / 4

Wie die Antwort entsteht

7:30 min 07:30 – 15:00
Sprecher:in B

Ziel: Die zwei Suchmechanismen und die Konfidenz-Pipeline verständlich machen — ohne Codezeilen, mit der Logik dahinter.

7:30
Architektur-Brücke, ein Diagramm. Wo diese Logik im System sitzt (API-Server, zwischen Retrieval und Antwort). + Ergänzung
8:30
Hybrid-Retrieval: Dense-Suche (Embeddings, Bedeutung) findet Umschreibungen; Sparse-Suche (Volltext, Wörter) findet exakte Fachbegriffe wie „hochriskant“. Beide werden fusioniert (Reciprocal Rank Fusion) — nicht addiert, weil ihre Skalen nicht vergleichbar sind. Bild: zwei Ranglisten, die zu einer verschmelzen.
10:30
Generierung: Ein Prompt zwingt das Modell, jede Aussage mit einer Quellenreferenz [n] zu belegen — Material, keine Behauptung ohne Beleg.
11:30
Die Konfidenz-Pipeline — vier Stufen, jede kann stoppen: Retrieval-Gate → Retrieval-Konfidenz → Citation-Check → Self-Check. Leitprinzip: fail-closed — im Zweifel «Weiss ich nicht» statt einer unsicheren Antwort.
hoch — Antwort + Quellen mittel — Antwort + Hinweis niedrig — «Weiss ich nicht»
Das ist exakt, was in der Demo zu sehen war — Kreis schliesst sich.
14:00
Warum das zählt: alle Schwellen sind über Konfiguration kalibrierbar, ohne Deployment — die Pipeline ist ein Instrument, kein fixer Code.
TEIL 3 / 4

Wie wir es gebaut haben

7:30 min 15:00 – 22:30
Sprecher:in C

Ziel: Architektur- und Prozessentscheide zeigen — nicht jede Codezeile, sondern warum so und nicht anders.

15:00
Architektur: Modularer Monolith statt Microservices, 4 Container (Webapp / API / Worker / DB) via Docker Compose. Bewusst einfach für ein Vierer-Team im Zeitrahmen. Zeigen: C4-Container-Diagramm.
17:00
Stack: FastAPI/Python auf PostgreSQL 17 mit pgvector (HNSW) und Volltextsuche — eine Datenbank für beide Suchen, kein separates Vektor-DB-System. Hintergrundjobs über pgqueuer, absichtlich ohne Redis. React/TypeScript vorne, LLM-Zugriff über LiteLLM (Provider austauschbar).
19:00
API-First: Jede Schnittstellenänderung beginnt in der OpenAPI-Spec, erst danach Backend und generierte Frontend-Typen — hält vier Leute an verschiedenen Enden synchron.
20:15
Ein konkreter Stolperstein: beim Vergleich mit einem lokalen Modell (Ollama) kürzte die Engine den Prompt stillschweigend bei 4096 Token — ausgerechnet die Systemanweisung mit dem Verweigerungsprotokoll fiel weg. Sichtbar wurde das nur über finish_reason und Token-Zahlen, die wir seither in jedem Eval-Lauf mitschreiben. Zeigt: Messmethodik ist Teil der Arbeit, nicht nur das Feature.
22:00
Prozess: Entscheide als ADRs dokumentiert, Backlog in GitHub Issues (T-01…T-61), jeder PR mit CI-Gate und Zweitreview.

7:30 min 22:30 – 30:00
Sprecher:in D

Ziel: Ergebnisse mit Zahlen statt Behauptungen zeigen, ehrlich benennen, was nicht geht — und mit einem Ausblick schliessen statt mit einem Mängelbericht.

22:30
Eval-Ergebnis, das Kern-Zahl. Out-of-Corpus-Fragen des Gold-Datasets: 90 % Verweigerungsquote gefordert, das Produktivmodell erreicht 95,5 %. + Ergänzung

Einordnung: lokale Modelle verweigern inhaltlich oft richtig, halten aber das erwartete Ausgabeformat seltener ein — kein reiner Qualitätsunterschied.
25:30
Überraschendster Befund: Citation-Coverage belohnt Kürze. Eine Ein-Satz-Antwort erreicht Coverage 1,0, landet im Band «hoch» — und der Self-Check läuft dort gar nicht mehr. Die knappste, selbstsicherste Antwort umgeht die meisten Sicherungen.
27:00
Was nicht ging: Umstieg auf Azure OpenAI EU (Voraussetzung für echte interne Dokumente im Betrieb) — im MVP bewusst nicht gemacht. Schwellen-Kalibrierung gegen das Gold-Dataset ist eine Hypothese, kein gemessener Optimalwert. Ein Re-Ranker/Cross-Encoder als zusätzliche Prüfschicht wurde verworfen, um kein zweites ML-Modell ins Deployment zu holen.
29:00
Ausblick: ein Satz, wo das Team als Nächstes ansetzen würde, wäre das Projekt kein Kursabschluss. + Ergänzung
