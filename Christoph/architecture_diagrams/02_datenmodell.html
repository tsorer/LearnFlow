Wie die LearnFlow-Datenbank aufgebaut ist

Acht Tabellen in PostgreSQL 17, aus app/models/tables.py — plus pgqueuer/pgqueuer_log als von der Queue-Library selbst verwaltete Infrastruktur ohne Fremdschlüssel-Bezug (siehe Architektur-Diagramm). Die Pfeile zeigen nicht nur, wer wen referenziert, sondern auch, was beim Löschen passiert — das ist an zwei Stellen bewusst unterschiedlich gelöst.

Identity — users Content — documents, chunks, quiz_questions Q&A — query_sessions, answers, feedback Utility — config CASCADE SET NULL

Löschverhalten

Was beim Löschen passiert

  • Ein user wird gelöscht → seine Dokumente, Sessions und Config-Änderungen bleiben, nur die Referenz wird NULL
  • Ein document wird gelöscht → seine chunks und quiz_questions werden mitgelöscht (CASCADE)
  • quiz_questions.chunk_id wird bei Ersatz der Quelle nur auf NULL gesetzt, nicht die Frage gelöscht — sie fällt zurück auf status = pending

Sonderfälle

Was im Schema nicht offensichtlich ist

  • feedback hat bewusst kein user_id-Feld — Pseudonymisierung (US-03)
  • documents trägt drei eigene „Uhren" fürs Worker/Reaper-Zusammenspiel: index_version (Optimistic-Lock), index_attempts (Reaper-Budget), index_progress_at (Fortschritts-Heartbeat, T-51) — keine mit onupdate
  • config ist generisches Key/Value, die Wertebereiche sind aber seit Migration 0009 per DB-CHECK + Trigger erzwungen, nicht nur im Code — aktuell an 5 Stellen verstreut (T-64)
