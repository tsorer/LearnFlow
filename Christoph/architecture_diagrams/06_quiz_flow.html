Wie aus Chunks ein freigegebenes Quiz wird

Zwei getrennte Mechanismen: Generierung (Stefan löst aus, das Modell schlägt vor, jede Frage einzeln geprüft) und Freigabe (ein Zustandsautomat mit zwei Regeln, die man beim blossen Lesen des Endpoints leicht übersieht). Es gibt hier keine Konfidenz-Pipeline wie beim Antwort-Pfad — das menschliche Review übernimmt diese Rolle (ADR-008).

Flow

Generierung — vom Klick bis zu fünf Vorschlägen

Zustandsautomat

Freigabe — pending · approved · rejected

approved — sichtbar für Lernende rejected — dauerhaft unsichtbar automatischer Übergang explizit per PATCH automatisch / extern ausgelöst

Fail-closed ohne Konfidenz-Pipeline

Der Mensch ist das Gate

  • Eine Frage ohne gültige Quellenangabe wird verworfen wie eine erfundene Zitation in ADR-008 — derselbe Massstab wie im Antwort-Pfad, nur trägt hier das Review die Verantwortung statt einer Schwelle
  • GET /quiz/questions zeigt Reviewern alle Status, Lernenden nur approved — derselbe fail-closed-Filter wie in der RBAC-Matrix, hier speziell für Fragen
  • GET /quiz/questions/sample zieht dagegen für jede Rolle nur aus approved — auch ein Reviewer sieht beim Quiz-Durchlauf selbst genau das, was ein Lernender sähe

Freigabe ist fragil, mit Absicht

Zwei Regeln, die man leicht übersieht

  • Wird der Text einer freigegebenen Frage geändert, ohne status mitzuschicken, fällt sie automatisch auf pending zurück — eine Freigabe gilt für den gesehenen Text, nicht auf Vorrat
  • Erneutes status=approved auf eine unveränderte, bereits freigegebene Frage ist keine zweite Freigabe — approved_at bleibt stehen (US-07 will den Moment der Freigabe, nicht jedes Speichern)
  • Eine Dokument-Ersetzung setzt nur approved-Fragen zurück auf pending — eine bereits rejected-Frage bleibt es
