Learning 03 · Issue #73

Der Test widerlegte die Fail-closed-Dokumentation

Der generierte Code bezeichnete den Fallback bei unlesbaren Konfigurationswerten als fail-closed. In der entscheidenden Fehlerrichtung war er fail-open.

Learning Dokumentation beschreibt die Absicht. Erst Tests gegen die Architekturentscheidung belegen, dass ein Fehler in die sichere Richtung führt.
Behauptung und Verhaltendurch Tests korrigiert
Der ursprüngliche Docstring versprach bei unlesbaren Werten einen Fallback auf sichere Standards: fail-closed, ADR-008

Tatsächliches Verhalten

gewünscht: 0,90 / 0,80 unlesbar verwendet: 0.75 / 0.45
Eine strengere Konfiguration führte zu lockereren Schwellen. Nur eine Log-Warnung machte den Fehler sichtbar.

Verhalten nach dem Fix

ungültiger Wert ConfigurationError Antwort unterdrückt
Ein vorhandener, aber unbrauchbarer Wert stoppt die Freigabe. Ein fehlender Wert darf weiterhin den definierten Default verwenden.
